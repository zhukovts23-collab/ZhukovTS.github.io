# Размещение

## Подходящий хостинг

Apache 2.4 с AllowOverride All, PHP 8.3+ (pdo_mysql, curl, mbstring, dom, SimpleXML, xsl), MySQL 8 или MariaDB 10.11, HTTPS, исходящие HTTPS-запросы к cbr.ru, meteoinfo.ru, ixbt.com. Предпочтителен российский дата-центр с проверяемой доступностью из РФ. Для Nginx требуется отдельно перенести запреты доступа из .htaccess в конфигурацию; без этого публиковать нельзя.

Один GitHub Pages или Cloudflare Workers не заменяет требуемый в методичке PHP/MySQL-хостинг.

## Обычный PHP-хостинг

1. Создать БД и отдельного пользователя с правами только на эту БД.
2. Загрузить файлы ветки, включая .htaccess. Не загружать .git, .env, tests и локальные preview-файлы.
3. На сервере скопировать app/config.example.php в app/config.local.php и заполнить DSN, логин, пароль, base_url (без завершающего слеша), случайный secret (не менее 32 символов). Не передавать секреты в чат или git.
4. Через терминал хостинга установить ADMIN_PASSWORD (14+ символов) и выполнить `php bin/install.php`. Извне установщик не запускается.
5. Выполнить `php bin/configure-url.php` для sitemap, robots и canonical. Загрузить заново актуальный search-index.json, если тексты изменены.
6. Проверить HTTPS, защищённые каталоги /app/, /bin/, /.git/, /tests/ — должны возвращать 403/404. Проверить admin.html, смену сеанса и публикацию новости.
7. Проверить все сценарии из VERIFICATION.md, особенно исходящие cURL и формы через реальный браузер.

Установка не содержит пароля администратора по умолчанию. Если нет SSH, можно использовать терминал панели или задачу cron для однократного запуска CLI. Не делать публичный установщик с открытыми реквизитами.

## VPS / Docker

compose.yaml поднимает Apache/PHP и MariaDB. БД не публикует порт наружу; web слушает только 127.0.0.1:8080. Перед публичным запуском подключить домен и HTTPS reverse proxy, выставить правильный APP_URL. Обновлять образы и сохранять резервные копии тома БД. Docker-сборка в данной среде не запускалась.

## Поисковые системы

После выбора окончательного адреса добавить сайт в Яндекс Вебмастер и Google Search Console, подтвердить владение выданным метатегом или файлом, отправить sitemap.xml и запросить обход главной. Это требует доступа владельца к соответствующим аккаунтам. Имеющийся Google verification-тег главной сохранён, но его наличие не доказывает подтверждение текущего домена. Индексация занимает время и не гарантируется. Позиции фиксировать по конкретному запросу и дате; не подменять их оценкой игр.

## Переход со старого адреса

До проверки нового хостинга старая GitHub Pages-версия сохраняется. После запуска заменить старую главную понятной ссылкой на новый адрес либо настроить переход, обновить README и ссылки. Не публиковать серверные страницы на Pages в качестве работающего PHP-приложения.
