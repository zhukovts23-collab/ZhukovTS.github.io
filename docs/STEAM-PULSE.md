# Пульс игр

Сервис `services/pulse.html`: дуэль двух игр по текущему числу активных игроков Steam, разница, доли выбранной пары, история собственных наблюдений с графиком и перемоткой.

Источник: официальный Steam Web API, ISteamUserStats/GetNumberOfCurrentPlayers/v1. Ключ не нужен. Допустимы только appid 730, 570, 578080, 440; произвольный URL пользователь передать не может. Данные относятся к подключённым к Steam активным игрокам, а не всем владельцам или аудитории других платформ.

## Обновление существующего сайта

1. Сохранить `api/pulse.php`, `js/pulse.js`, `css/pulse.css`, `services/pulse.html`, `database/pulse.sql`, `bin/update-pulse.php`. Обновить `services.html`, `search-index.json`, `database/schema.sql`, `bin/configure-url.php`.
2. Из корня сайта выполнить `php bin/update-pulse.php`. Эта операция создаёт только отсутствующие таблицы, повторный запуск безопасен. Для новой установки таблицы уже входят в schema.sql.
3. Выполнить `php bin/configure-url.php`: canonical, robots.txt, sitemap.xml и sitemap.txt, включая новый сервис. Сохранить Google verification meta в index.html.
4. Проверить `/api/pulse.php`, затем `/api/pulse.php?left=578080&right=440`. Для каждой игры должны прийти целое players и время sampled_at. При сбое источника выдаются сохранённые данные с stale=true либо players=null, без вымышленных значений.
5. Неподдерживаемые, одинаковые и массивные параметры возвращают 400; POST возвращает 405. Повторное обращение ранее 5 минут не добавляет замер.
6. Открыть страницу, сменить пару. Через 5 минут обновить для второго реального наблюдения, проверить график и перемотку.

Сервер запрашивает источник не чаще раза в 300 секунд на игру; GET_LOCK предотвращает одновременный опрос. HTTPS, лимит ответа 64 КиБ, таймаут 8 секунд. История хранится в MySQL; при успешном обновлении удаляются наблюдения старше 72 часов. Ответ и интерфейс показывают не более 288 последних точек за этот период. Разные игры могут иметь разное время замера; это явно указано в интерфейсе. История образуется при обращениях, а не непрерывно. Один замер не изображается линией графика.

## Для защиты

Открыть «Сервисы → Пульс игр», выбрать разные игры и нажать «Сравнить и обновить». Показать время и источник, расчёт долей, таблицу. Если есть минимум два наблюдения — перемотать график. Объяснить цепочку: браузер → собственный PHP endpoint → Steam API → кэш и история MySQL → JSON → карточки и SVG. Не называть сервис уникальным во всём интернете: оригинальна его реализация внутри GameVerse.

## Проверка 03.11.2026

PHP lint, node --check и bash -n пройдены. Реальный PHP-контроллер возвращает 400 для одинаковых игр, неизвестного appid, массива вместо параметра и SQL-подобной строки; POST возвращает 405. Проверены локальные ресурсы страницы, поля формы, отсутствие повторяющихся id, ссылки из списка сервисов и индекса поиска. Отдельная MariaDB 10.11 в bootstrap-режиме приняла схему, повторную миграцию, запись и запрос истории. Полная проверка PDO и интерфейса на действующем Beget ещё требуется: панель в браузере возвращает HTTP 502, прямое подключение из рабочей среды завершается таймаутом.

Подготовлен `bin/deploy-pulse.sh`: размещает заранее проверенную версию 9164a8c, сохраняет копии затронутых файлов в приватной папке аккаунта, добавляет отсутствующие таблицы, обновляет карты сайта и проверяет первый ответ Steam. Личные настройки app/config.local.php не копируются и не заменяются. Установка считается завершённой только после строки DEPLOYED и проверки страницы в браузере.

Дополнительная живая проверка Google 03.11.2026 выявила ошибку доступа к robots.txt. Устанавливающий скрипт проверяет HTTP 200 для главной, robots.txt, обеих карт и нового сервиса. Права SEO-файлов устанавливаются 644. Требуется убедиться, что доступ восстановлен, прежде чем считать сайт готовым к сдаче.
