# GameVerse — восстановление на другом PHP/MySQL-хостинге

Подготовлено 3 ноября 2026 года. Этот пакет не требует доступа к Beget.

## Что сохранено

Исходный код 26 HTML-страниц, изображения, XML/XSL-каталог 20 игр, PHP API, структура MySQL, 3 исходные новости и новый сервис Steam Pulse. Новые сообщения, публикации, голоса и статистика с Beget в этот архив не входят: свежий экспорт его БД недоступен. Это исходный набор для новой копии сайта, а не полный бэкап прежнего сервера. История Steam начнёт накапливаться заново после успешных обращений к API. Новый сервис ещё требует проверки на выбранном хостинге.

## Требования

PHP 8.3 или выше; расширения pdo_mysql, xsl, mbstring, curl, dom, simplexml; MySQL 8 или MariaDB 10.11; Apache с .htaccess и mod_rewrite. Для внешних API нужны исходящие HTTPS-соединения. Для управления администратором использовать HTTPS или SSH-туннель. Новый хостинг и технический домен ещё не выбраны и не настроены.

## Размещение

1. Создать тестовый аккаунт обычного виртуального хостинга с PHP/MySQL, без оплаты и покупки домена. Для Спринтхост тариф X-1 заявлен с тестом 30 дней; проверить, что при регистрации выбран именно тест. Договор/регистрацию подтверждает владелец аккаунта.
2. Создать сайт на предоставленном техническом домене, выбрать PHP 8.3 и включить нужные расширения. Проверить наличие HTTPS для нового адреса. Адрес zhukovop.beget.tech принадлежит инфраструктуре Beget — переназначить его из чужой панели нельзя.
3. Создать отдельную пустую базу и пользователя. Сохранить реквизиты только на новом сервере. На старом хостинге ничего не удалять.
4. Содержимое каталога site/ из архива загрузить в корень документов нового сайта. Должны попасть также .htaccess в корне и закрытых каталогах. Не загружать корневые README-FIRST.md и инструкции в открытые папки сайта.
5. На сервере скопировать app/config.example.php в app/config.local.php. Заполнить dsn, user, password и base_url (реальный новый HTTPS-адрес без завершающего /). Для secret получить свежую случайную строку командой `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`, сохранить её в конфигурации, не использовать старые секреты Beget. Сам config.local.php не публиковать и не отправлять в GitHub.
6. В терминале нового хостинга перейти в корень сайта и выполнить `bash bin/install-host.sh`. Если команда php указывает на старую версию, использовать `GV_PHP_BIN=/путь/к/php83 bash bin/install-host.sh` с путём из документации провайдера. Ввести новый отдельный пароль администратора дважды (минимум 14 символов, ввод скрыт). Скрипт проверяет расширения и соединение с БД, создаёт таблицы, импортирует исходные игры и новости, создаёт admin, обновляет robots.txt и обе карты сайта на новый адрес. Повторный запуск не меняет существующий пароль и новости.
7. Если нет терминала, файл site/database/restore-from-source.sql можно импортировать через phpMyAdmin в пустую БД. Он добавляет таблицы, игры и исходные новости, но НЕ создаёт администратора. Настройку администратора, URL и SEO нужно завершить отдельно. Открытый веб-установщик или диагностический phpinfo на публичном сайте не создавать.
8. Проверить главную, каталог/фильтры, XML, БД, новости, гостевую книгу, форум, RSS/экспорты, сервис бюджета и Steam Pulse. Проверить HTTP 200 у robots.txt, sitemap.xml, sitemap.txt; закрытый app/config.local.php должен отдавать 403/404 без тела конфигурации.
9. После успешного запуска добавить НОВЫЙ адрес в Google Search Console как отдельный ресурс и отправить его sitemap.xml. Индексация старого адреса на новый не переносится автоматически. Успешная обработка карты и появление в поиске зависят от поисковика.

## Важные границы

В архиве нет конфигурации, паролей или ключей Beget. Google verification meta сохранены в HTML как публичное подтверждение владельца, но новый ресурс всё равно требует проверки в Search Console. Статический GitHub Pages не исполняет PHP и не заменит серверные задания 3–4 лабораторных. Установка на новый хостинг пока не выполнена; факт наличия кода не является проверкой нового сервера.
